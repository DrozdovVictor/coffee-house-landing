Стек
Фронтенд: ReactTs, Zustand, tailwind, vite.

Бэкенд: Vercel Serverless Functions (/api/lead).

База данных: Firebase Firestore (через firebase-admin).

Что делал сам, а что ИИ
ИИ (Claude/GPT): Генерация базовой структуры React-компонентов, написание чернового варианта Zustand-стора, каркас серверной функции на Node.js, функции нормализации телефона и отправки в Telegram.

Сам: Настройка проекта, верстка и адаптив, интеграция Firebase Admin SDK, решение проблем со сборкой Vercel и обработка ошибок на фронтенде.

Где ИИ ошибся и как я это заметил
Проблема с модулями Vercel: ИИ предложил вынести хелперы (firebase.ts, telegram.ts) в папку server вне директории api. Vercel отказался собирать функцию (ERR_MODULE_NOT_FOUND). Пришлось вручную "инлайнить" весь серверный код напрямую в api/lead.ts, чтобы сделать функцию самодостаточной.

Парсинг JSON ключа: ИИ предложил хранить приватный ключ Firebase одной длинной строкой в .env. Vercel неправильно обрабатывает переносы строк \n в переменных окружения на Windows/при сборке, из-за чего ключ ломался. Пришлось перейти на передачу целого JSON-файла в переменную FIREBASE_SERVICE_ACCOUNT.

Что не успел
К сожалению, из-за ограничений по времени я не успел полностью закрыть дедлайн по бэкенду (начал делать в воскренье):

Форма не сохраняет данные: Серверная функция успешно разворачивается, валидирует телефон и принимает POST-запросы. Однако при попытке записи в Firestore возникает ошибка 16 UNAUTHENTICATED. Проблема кроется в специфике передачи приватного ключа Firebase через Environment Variables на хостинге Vercel.

Telegram-бот: Код для дублирования заявок в Telegram написан (с таймаутом и обработкой ошибок), но не протестирован из-за общей блокировки бэкенда.

Хранение заявок
Выбрал Firebase Firestore. В serverless-среде Vercel (как и на большинстве бесплатных хостингов) файловая система эфемерна — файл или SQLite-база не переживут холодный старт функции. Firestore бесплатен в рамках квот, поддерживает транзакции и serverTimestamp. Дедупликация реализована двухуровнево: проверка последних заявок по номеру в транзакции + детерминированный ID документа на 10-минутный интервал (защита от параллельных запросов).
